# iFlow Core on AWS (Phase 10.4)

Infrastructure as code (AWS CDK, Python) for the account & E2E sync API in `api/`. Everything below is
reviewable before anything is created: `scripts/deploy.sh --diff` shows the full change set.

```
Internet ──HTTPS──▶ Load balancer + WAF ──▶ ECS Fargate (api/ container) ──TLS──▶ RDS PostgreSQL 16
                    ACM certificate            Secrets Manager: JWT key, pepper,     (private subnets,
                    api.iflowcore.com          DB login (injected at start)          encrypted, backups)
                                               SES: verification / reset email
```

| Piece | Choice | Why |
|---|---|---|
| Compute | ECS Fargate, 0.25 vCPU / 0.5 GB, 1–3 tasks (CPU autoscaling), rollback on failed deploys | App Runner would need a NAT gateway (≈$32/mo) to reach Google and SES from the VPC |
| Network | 2 AZs, **no NAT gateway**. Tasks in public subnets, reachable only from the load balancer; database in isolated subnets with no internet route | Cost, and the database is never reachable from outside |
| Database | RDS PostgreSQL 16, `db.t4g.micro`, gp3 20→100 GB, encrypted, TLS-only, 7-day backups, deletion protection, snapshot on delete | Plan 10.4 |
| Secrets | DB password generated by RDS; JWT signing key + code pepper generated by `scripts/create_app_secret.py`, straight into Secrets Manager | Nothing secret in the template, image, logs or app binaries |
| TLS | ACM certificate for `api.iflowcore.com`, TLS 1.2+, HTTP → HTTPS redirect | |
| Email | SES domain identity for `iflowcore.com` (DKIM, MAIL FROM `mail.iflowcore.com`); the API may only send as `no-reply@iflowcore.com` | |
| Edge | WAF: 100 req / 5 min per IP on `/v1/auth/*`, 2000 overall, AWS IP-reputation, common and known-bad-input rules. **Request sampling off** (samples would store bearer tokens) | |
| Migrations | Each new image runs `alembic upgrade head` as a one-off task **before** the service updates; a failed migration fails the deploy | A new image never serves an old schema |
| Operations | Alarms to your email: API down, 5xx, p95 latency > 2 s, DB CPU, DB storage. Monthly budget alert (80 % actual, 100 % forecast). Logs kept 30 days | |

The server only ever stores ciphertext for synced data (Phase 10.3); logs hold request metadata only.

## Statement-format CDN (`IflowCoreFormats`, Phase 11)

A second stack, always in us-east-1 because CloudFront certificates must live there:
- a private, versioned, TLS-only S3 bucket behind CloudFront (Origin Access Control) at
  `formats.iflowcore.com`;
- GET/HEAD only, read-only CORS for the web app, and security headers;
- `IflowFormatsPublisher`, a least-privilege policy to upload under `v1/` and invalidate.

`scripts/deploy.sh` deploys it with the API. Then:
1. Copy the `ServiceEnv` output (bucket and distribution id) into the Admin Console under
   My account → Publishing to the CDN.
2. Add the `formats` CNAME from `dns_records.py`.

Cost is pennies a month at this size.

## First deploy

Things only you can do are marked **(you)**.

1. **(you) AWS account.**
   - Create it at aws.amazon.com and turn on MFA for the root user.
   - In IAM Identity Center, create an admin user for yourself. Use it from now on, not the root user.
2. **(you) Tools on this machine:**
   - Install the AWS CLI v2 (the official installer from aws.amazon.com/cli).
   - Install Docker: `sudo apt install docker.io`, then `sudo usermod -aG docker $USER` and log out and
     back in.
   - Node.js 22 and the CDK CLI are already installed in `~/.local/node` (add `~/.local/node/bin` to your
     PATH).
   - The Python environment is `infra/.venv`. To recreate it:
     `python3.12 -m venv infra/.venv && infra/.venv/bin/pip install -r infra/requirements.txt`.
3. **(you) Sign in:** run `aws configure sso` and name the profile `iflow`. Later sessions only need
   `aws sso login --profile iflow`. Never paste access keys anywhere.
4. **Settings:** in `infra/cdk.json`, set `alert_email` (and optionally `account`). Everything else has
   working defaults.
5. **One-time CDK bootstrap:**
   `cd infra && AWS_PROFILE=iflow cdk bootstrap aws://<account-id>/us-east-1`
6. **Review, then deploy:**
   ```bash
   cd infra
   AWS_PROFILE=iflow scripts/deploy.sh --diff     # what will be created
   AWS_PROFILE=iflow scripts/deploy.sh            # create it (≈ 20 min the first time)
   ```
7. **(you) DNS**, while the deploy waits on the certificate:
   - In a second terminal, run `AWS_PROFILE=iflow .venv/bin/python scripts/dns_records.py`.
   - Add the records it prints at your DNS host: the two certificate validation CNAMEs first (api and
     formats), then the API and formats CNAMEs, 3 DKIM CNAMEs, MAIL FROM MX + SPF and an optional DMARC
     record.
   - If the domain already has an SPF or DMARC record, merge rather than add a second one.
   - Re-run with `--check` to see which records are visible.
8. **(you) SES production access.** New accounts can only email verified addresses.
   - In the SES console, choose "Request production access": transactional email only (sign-up
     verification and password reset), low volume, bounces handled.
   - Until it's approved, verify your own address in SES to test sign-up.
9. **Smoke test:** `.venv/bin/python scripts/smoke_test.py`
   - It checks TLS, `/healthz`, `/readyz` (the database), the HTTPS redirect, anonymous calls refused,
     CORS, and that API docs are off.
   - It creates no accounts and sends no email.
10. **Apps:** 0.12.0 uses `https://api.iflowcore.com` for "Sign in to iFlow" and
    `https://formats.iflowcore.com` for statement formats by default. Nothing to configure.

## Later deploys

Run `AWS_PROFILE=iflow scripts/deploy.sh`. It rebuilds the image, runs migrations, rolls the service, and
rolls back automatically if new tasks fail their health checks.

## Operations

- **Logs:** CloudWatch `/iflow-core/api` and `/iflow-core/api/migrate`.
- **Platform connections (token broker):** when a platform (Uber) issues iFlow an OAuth client, put
  `{"uber-driver-api": {"token_url": "https://auth.uber.com/oauth/v2/token", "client_id": "…",
  "client_secret": "…"}}` in the `iflow-core/api/integration-clients` secret, then redeploy. It starts
  as `{}`.
- **Google sign-in:** add the OAuth client IDs to `google_client_ids` in `cdk.json` and deploy.
- **Rotating the JWT signing key:**
  1. Generate a new key.
  2. Put the current public key in `IFLOW_API_JWT_PREVIOUS_KEYS` (`kid=PEM`).
  3. Store the new private key in the secret and bump `jwt_key_id`.
  4. Deploy. Existing sessions keep working until they refresh.
- **Restoring the database:** RDS console → Snapshots or point-in-time restore → a new instance.
  Automated backups are kept 7 days (`backup_days`).
- **Tearing down:** the stack has termination protection and the database has deletion protection.
  Both are deliberate; turn them off in the console first. Deleting the stack keeps a final DB snapshot
  and the log groups.
- **Tests:** `cd infra && PATH=~/.local/node/bin:$PATH .venv/bin/pytest -q` synthesizes the stack and
  checks its security properties (no AWS account needed).
